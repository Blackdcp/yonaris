---
title: Telemetry
description: Yonaris telemetry defaults, explicit configuration, and the settings that keep it disabled.
---

Yonaris telemetry is **disabled by default**. New configurations generated by `elmo init` include:

```dotenv
DISABLE_TELEMETRY=1
```

The compatible CLI contains no built-in analytics project key or endpoint. It also does not ask for a newsletter email. With the default configuration, CLI initialization and upgrade events are local no-ops.

## Explicit first-party configuration

A future Yonaris-owned telemetry deployment must be configured with both of these values:

```dotenv
YONARIS_POSTHOG_KEY=your-yonaris-project-key
YONARIS_POSTHOG_HOST=https://telemetry.example.com
```

The CLI reads them from the shell environment or the deployment `.env`. Both values are required, and `YONARIS_POSTHOG_HOST` must use HTTPS. A missing key, missing host, malformed URL, or non-HTTPS host leaves telemetry disabled.

To explicitly enable that configured destination, remove `DISABLE_TELEMETRY` from the shell and deployment `.env`. Setting `DISABLE_TELEMETRY` to any non-empty value always takes precedence and prevents CLI events from being sent.

## Data used when explicitly enabled

CLI events may include:

- the random `DEPLOYMENT_ID` stored in the deployment `.env`;
- CLI version, operating system, architecture, and Node.js version;
- command names and non-secret setup options;
- whether scraper and direct-model providers are configured.

The CLI event path does not include API keys, `.env` contents, brand names, prompt text, scraped responses, file paths, or hostnames.

## Compatibility names

The `elmo` command and `DEPLOYMENT_ID` remain upstream-compatible technical identifiers. They do not select an analytics destination. Only the explicit `YONARIS_POSTHOG_KEY` and HTTPS `YONARIS_POSTHOG_HOST` pair can configure the Yonaris CLI destination.
