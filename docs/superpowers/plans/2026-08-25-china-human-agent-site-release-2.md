# Yonaris China Human and Agent Site — Release 2 Plan

**Goal:** Ship the complete Chinese regional website as an independently written, decision-led Human experience with paired Chinese Agent fact pages and the approved three-field phone lead path.

**Reference boundary:** Borrow only the market-change framing, conclusion-first hierarchy, complete service sequence, and China-to-global capability narrative identified in the approved design specification. Keep the Yonaris wordmark, palette, factual boundaries, and product model.

## Task 1 — Regional shell and content model

- Add a dedicated Chinese shell with official light/dark wordmarks, primary navigation, a visible `人类阅读 / Agent 阅读` switch, mobile navigation, section navigation, and footer.
- Author Chinese content around `市场变化 → 业务后果 → 可观察证据 → 服务过程 → 下一步`.
- Define five Chinese anxiety questions and shared product, service, evidence, and global-service records.
- Test brand assets, route-preserving switches, field labels, and absence of role-first segmentation.

## Task 2 — Complete Chinese Human routes

- Rebuild `/zh`, `/zh/product`, `/zh/approach`, `/zh/research`, `/zh/geo`, `/zh/company`, and `/zh/diagnostic` with a distinct visual anchor on every page.
- Home: question scene, market shift, product path, service path, China/global context, Human/Agent parity, and diagnostic close.
- Product: Chinese product workbench.
- Approach: operable delivery path showing customer input, Yonaris work, output, and human review.
- Evidence: expandable evidence record and definitions without invented metrics.
- AI visibility: Chinese answer relationship map and configured regional scope.
- Company: local-market understanding, global service behavior, responsibility, and verified-trust boundaries.
- Diagnostic: use the live `姓名、电话、公司` form and confirmed server email delivery.

## Task 3 — Chinese Agent companions

- Add `/zh/agent` and topic companions for product, approach, research, geo, company, and diagnostic.
- Render branded HTML by default and locale-specific Markdown when `Accept: text/markdown` is preferred.
- Keep Human canonicals, facts, claims, boundaries, locale, and topic links aligned.
- Extend manifest and machine discovery without creating a second factual store.

## Task 4 — Release verification

- Run regional page, interaction, form, parity, manifest, and negotiation tests.
- Run TypeScript and the marketing production build.
- Inspect all Chinese Human pages and representative Agent pages at desktop, tablet, and mobile widths.
- Run public-output and restricted-terminology audits, then commit and push the complete release.
